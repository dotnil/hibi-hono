# Сессии
## Требования
- Зарегистрированный пользователь может войти с корректными учётными данными.
- При успешном входе сервер устанавливает cookie с JWT.
- Пользователь с действительной сессией может получить свой идентификатор и email.
- Без действительной сессии доступ к текущему пользователю запрещён.
- При выходе сервер отправляет указание удалить cookie авторизации.

## Пользовательские сценарии
### Успешный вход
- Клиент отправляет `POST /sessions` с корректными email и паролем зарегистрированного пользователя.
- Сервер возвращает `200` с `{ ok: true }`.
- Сервер устанавливает cookie `jwt` с JWT.

### Получение текущего пользователя
- Клиент отправляет `GET /sessions/current` с действительной cookie `jwt`.
- Сервер возвращает `200` с идентификатором и email текущего пользователя.
- Ответ не содержит хеш пароля.

### Выход
- Клиент отправляет `POST /logout`.
- Сервер возвращает `200` с `{ ok: true }`.
- Сервер отправляет cookie `jwt` с указанием удалить её.
